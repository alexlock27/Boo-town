# RUN14 U2.3 — the hit window, measured

Generated by `tests/lib/run14_hitwindow.mjs` against the live judge. The window is not
a feel judgement: it is instrumented, and this is what the instrument says.

## The constants as shipped

| | ms | meaning |
|---|---:|---|
| `PERFECT_MS` | 110 | a "Perfect!" — still a real achievement |
| `GOOD_MS` | 220 | the judged window either side of the line |
| `NEAR_MS` | 380 | outside GOOD but clearly aimed: a warm "so close!" — NEVER silence |

At this round's tempo one beat is 517ms, so the judged window spans
0.85 beats — and the hit-zone band is drawn to exactly that height.

## 2. Why 220 and not 160

A nine-year-old's press error against a visual beat is roughly normal with a LATE bias
(she sees the note reach the line, then presses). Modelling that as mean +45ms, sigma
95ms, this is the share of genuine attempts each candidate window would accept:

| window ±ms | attempts accepted |
|---:|---:|
| 80 | 54.7% |
| 120 | 74.3% |
| 160 | 86.9% |
| 180 | 91.5% |
| 200 | 94.2% |
| 220 | 96.6% |
| 240 | 97.9% |
| 280 | 99.3% |
| 320 | 99.8% |
| 400 | 100.0% |

The old 160ms window rejected roughly one genuine attempt in six — and rejected it
SILENTLY, which is what U0 recorded as "my tap did nothing". 220ms accepts ~97%, and
past ~240ms the curve flattens: the extra width stops buying accuracy and starts
buying accidental hits. 220ms is where the returns stop, so 220ms is the constant.

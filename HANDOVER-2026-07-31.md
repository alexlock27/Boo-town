## 3. DO THIS FIRST — the outstanding full board

```bash

```

Then for anything red:

1. **Re-run it serially** — `node tests/<name>.mjs`. Roughly half of all board failures are
   parallel-load flakes.
2. **If it still fails, A/B it against `main`** before believing it is new:
   ```bash
   git worktree add --detach /tmp/wt-main main
   cd /tmp/wt-main && python _serve.py 8000    # tests hardcode 127.0.0.1:8000
   cd <repo> && node tests/<suite>.mjs         # repo has node_modules; test files usually identical
   ```
   (Check the test file is identical on both branches first: `git diff --quiet main..<branch> -- tests/<suite>.mjs`.)
3. **If it fails on both, it is pre-existing** — log it, do not fix it as part of other work.

### Five testing lessons that cost hours today. Do not relearn them.

1. **`_runall.sh` does NOT start a server.** It has no server code in it at all. If nothing is
   serving 8000, all 181 suites "fail" instantly. This happened twice and produced two entirely
   fictional 175-failure reports.
2. **Never edit a file while a board is in flight.** It invalidates the run. Also happened.
3. **8 lanes is too many on this machine** (32 cores notwithstanding) — it produced ~21 false
   failures. **6 is the sweet spot.**
4. **A red suite is not a bug until it fails serially AND differs from `main`.**
5. **Check the build pack before "fixing" a failing test.** Five suites today were asserting
   behaviour that `_programme/RUN19.md`/`RUN20.md` explicitly told us to change (catchphrase rate
   0.2→0.45, the `"Put «name» somewhere?"` button, the pirate's spyglass idle, Bounce digit mode).
   **I twice nearly reverted work Alex had asked for.** Grep `_programme/` first, every time.

## 3b. Localhost: use it for the test board ONLY. Do not send Alex there.

**Alex's standing instruction: he does not want to mess about with localhost or cache problems
again.** A full session was burned on it. Here is the settled position — do not re-open it.

**For you (automated testing): a local server is unavoidable and fine.** Every Playwright suite
hardcodes `127.0.0.1:8000`. One command, then forget about it:

```bash
python _serve.py 8000        # sends no-store, serves its own folder, prints only problems
```

**For Alex (looking at the game): the live site, after you deploy.** Do not ask him to run a
local server, hard-refresh, clear a cache, or read a console. If you want him to see something,
ship it and give him the URL.

**The cache problem is SOLVED. Do not re-diagnose it.** For the record, so nobody chases it again:

- `sw.js` matches with `ignoreSearch: true`, so `?v=` query bumps in `index.html` are **inert** for
  an installed PWA. Only a **`BUILD_STAMP` bump** invalidates the cache. That is the mechanism —
  use it, and do not add version queries expecting them to help.
- `js/main.js` now **deletes** stale service-worker caches on localhost (unregistering alone never
  emptied them, and never stopped the worker already serving the current page) and reloads once,
  guarded against a loop.
- `_serve.py` serves its own folder, hops off a busy port loudly, and sends `no-store` with no ETag.
- A leftover server from an earlier session squatting on 8000 and serving an **old copy of the
  folder** was the actual cause of "my changes aren't showing up", twice. **Kill stray servers
  before and after any test run**, and never leave one running at the end of a session:
  ```bash
  netstat -ano | grep -E ":80[0-9][0-9] " | grep LISTENING
  ```

**After deploying, verify on the live URL yourself** — fetch the stamp, and if it is a visual
change, drive the live site with Playwright and look. That is your job, not his.

## 8. Practical notes

- **Run the app locally:** double-click `START BOO TOWN.bat`, or `python _serve.py 8000`. It
  self-locates (serves its own folder, not the shell's cwd), hops to the next free port if 8000
  is busy and says so loudly, sends `no-store`, and prints only problems.
- **Stale-cache trap (solved, but know it):** `sw.js` matches with `ignoreSearch: true`, so `?v=`
  query bumps in `index.html` do **nothing** for an installed PWA. Only a `BUILD_STAMP` bump
  invalidates the cache. `js/main.js` now deletes stale SW caches on localhost and reloads once.
- **A screen that fails to load prints the real error on localhost only** (router catch in
  `js/main.js`). That catch wraps the dynamic *import*, never `mount()` — so landing there always
  means a module failed to fetch or parse.
- **Seed save for testing:** `REVIEW-SEED-19-20.txt` — v23, 900 stars, all 18 room dressings
  owned, Full tier, new object types pre-placed. Paste into the game's restore box.
- **Do not touch** `bootown-qa-seed-code-for-alex.txt` or `seed code for testing-alex only.pdf`.
- **Deploy gate (house law, `CLAUDE.md`):** bump `BUILD_STAMP` in `sw.js` → append a What's New
  block in `data/whatsnew.js` with `version` equal to that stamp → push → **fetch the live URL and
  confirm the new stamp is serving** → update `PROGRESS.md`. Gate suites: `r18a-buildstamp`,
  `r17x4-whatsnew`, `m3-pwa`, `r12s1-routes`.
- **Save migrations:** any schema change = one new step in `migrate()` + a VERSION bump, lossless.
  Gotcha: `deepDefaults` runs BEFORE `migrate()`'s body, so "key is missing" checks are never true
  for an old save. Migrations are covered across nine eras by `r8p1-migrations`.
- **Offline law:** every new `js/` or `data/` file must be added to `sw.js` `ASSETS[]` **in the
  same commit**, or offline silently breaks.
- Branches: `main` (live), `fix-r20-qa` and `review-19z2-20` (merged, kept for history).
